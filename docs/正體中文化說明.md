# LiteLLM 管理介面 正體中文化說明

> 本文件為非技術人員撰寫,說明本專案如何讓 LiteLLM 的英文管理介面顯示為正體中文,以及日常維護時該怎麼操作。

---

## 一句話總結

我們**沒有修改 LiteLLM 的程式碼**,而是在打包系統時,把一本「英翻中字典」和一位「隨侍翻譯員」放進管理介面的每一個網頁裡。之後每當畫面上出現英文字,翻譯員就立刻查字典,把它換成中文顯示給你看。

---

## 用一個比喻來理解

想像 LiteLLM 是一棟原廠進口的英文展示館:

- **字典(`zhtw/dict.json`)**
  一本厚厚的對照手冊,收錄了約 **4,200 多條**「英文原句 → 中文譯句」的對照。
  例如:`Virtual Keys → 虛擬金鑰`、`Teams → 團隊`、`Usage → 用量`。

- **隨侍翻譯員(`zhtw/inject.js`)**
  一位站在每個房間門口的翻譯員。訪客(你)看到的任何英文告示,他都會**即時**查手冊換成中文。
  更厲害的是,展示館的告示會不斷更換(網頁內容是動態產生的),翻譯員會**持續盯著畫面**,新出現的英文一冒出來就馬上翻譯,你幾乎察覺不到過程。
  他還懂一些「句型」:像 `Page 3 of 10` 這種數字會變動的句子,手冊查不到,但他知道套用句型翻成「第 3 頁,共 10 頁」。

- **裝訂工人(`zhtw/patch_ui.py`)**
  在「打包出貨」(建置 Docker 映像檔)的那一刻,工人會把字典和翻譯員**縫進**管理介面的每一頁網頁裡(目前版本共 48 頁),並順手把舊式的登入頁面直接改成中文。做完這一次,以後每次開網頁,翻譯員就自動就位。

---

## 為什麼要用這種做法?

| 做法 | 問題 |
|---|---|
| 直接改 LiteLLM 原始碼翻譯 | 每次官方更新版本,改過的地方全部要重做,維護成本極高 |
| 等官方推出中文版 | 官方目前沒有正體中文介面,遙遙無期 |
| **字典注入(本專案採用)** | **完全不動原始碼**,升級版本時字典照常可用,新增的英文字頂多先顯示英文,不會壞掉 |

這種做法的核心優點是「**優雅降級**」:就算某句英文字典裡沒有,畫面也只是顯示原本的英文,系統功能完全不受影響。

## 整體運作流程

```
【打包階段】(執行 docker compose build 時,只做一次)

  官方 LiteLLM 映像檔
        │
        ▼
  裝訂工人 patch_ui.py 啟動
        │  1. 讀入字典 dict.json + 翻譯員 inject.js
        │  2. 塞進管理介面的每一個 HTML 網頁
        │  3. 把舊版登入頁的英文直接改成中文
        ▼
  產出公司專用映像檔 litellm-zhtw


【瀏覽階段】(每次有人打開管理介面時,自動發生)

  你打開網頁 ──► 翻譯員甦醒
                    │  1. 先把整頁現有的英文全部翻一遍
                    │  2. 之後持續監看畫面變化
                    │  3. 新英文一出現 → 查字典 → 換成中文
                    ▼
              你看到的是正體中文介面
```

翻譯員很小心,不會亂翻不該翻的東西:程式碼區塊、你自己輸入的文字框內容,都會自動跳過。

## 日常操作指南

### 情況一:發現某個地方還是英文(字典漏字)

1. 把畫面上那句**完整的英文**抄下來(大小寫、標點都要一模一樣)。
2. 打開 `zhtw/dict.json`,找到字母順序相近的位置,加上一行:

   ```json
   "那句英文": "對應的中文翻譯",
   ```

   > 注意:每行結尾要有逗號(最後一行除外),前後要有英文雙引號。

3. 在專案資料夾開啟終端機,執行:

   ```
   docker compose build
   docker compose up -d
   ```

4. 用瀏覽器**強制重新整理**(按 `Ctrl + F5`),確認該處已變成中文。

### 情況二:升級 LiteLLM 版本

1. 照平常方式更新(重新 build 即可,Dockerfile 會抓官方最新的 stable 版)。
2. 升級後,**新版新增的英文介面文字會暫時顯示英文**——這是正常的,不是故障。
3. 把看到的新英文依「情況一」的步驟補進字典即可。

### 情況三:翻譯有誤想修正

直接在 `zhtw/dict.json` 找到那句英文,修改冒號後面的中文,再照「情況一」的第 3、4 步重建即可。

## 三個檔案速查表

| 檔案 | 角色 | 你會需要動它嗎? |
|---|---|---|
| `zhtw/dict.json` | 英翻中字典(約 4,200 多條) | **會**——補漏字、修翻譯都改這裡 |
| `zhtw/inject.js` | 網頁裡的即時翻譯員 | 幾乎不用動 |
| `zhtw/patch_ui.py` | 打包時的裝訂工人 | 幾乎不用動 |

## 常見問題

**Q:改了字典之後,為什麼畫面沒變?**
A:要先重建並重啟(`docker compose build` + `docker compose up -d`),然後瀏覽器按 `Ctrl + F5` 強制重新整理。瀏覽器快取是最常見的原因。

**Q:字典裡找不到我看到的那句英文?**
A:抄英文時必須**一字不差**(包含大小寫與標點)。另外,連續的空白會被視為一個空白,所以句中多幾個空格沒關係,但字要完全相同。

**Q:這樣會不會拖慢系統?**
A:不會有可感知的影響。翻譯發生在你自己的瀏覽器裡,查字典是瞬間完成的,伺服器端(API 服務本體)完全沒有被更動。

**Q:API 回覆的內容也會被翻譯嗎?**
A:不會。這套機制**只翻譯管理介面的畫面文字**,模型回答的內容、API 的資料完全不受影響。

**Q:萬一整個中文化壞掉了怎麼辦?**
A:最壞情況就是介面變回英文,功能一切正常。因為我們從未修改 LiteLLM 本體,把 Dockerfile 換回官方映像檔就能完全還原。

## 當初字典是怎麼做出來的?(背景知識)

字典並非人工一條條抄寫,而是:

1. 從 LiteLLM 官方原始碼(v1.92.0 版)中,用程式自動萃取出介面上所有英文字串,約 4,353 條。
2. 交由 AI 分成 8 批平行翻譯,並使用**固定術語表**確保全站用詞一致(例如 Virtual Key 一律翻「虛擬金鑰」、Spend 一律翻「花費」)。
3. 合併、去重後成為現在的 `zhtw/dict.json`。

日後若要大版本更新字典,可比照此流程重新萃取、翻譯新增的字串。
